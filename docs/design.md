# Regolith 设计文档

## §1 目标与定位

Regolith（月壤）是一个嵌入式的 LSM-tree 键值存储，用 MoonBit 从零实现，
仅依赖 moonbitlang/core 与 moonbitlang/x 两个官方包。设计目标：

1. **可移植**：纯 MoonBit 实现，不依赖任何系统调用（文件 IO 全部经由
   `moonbitlang/x/fs` 的抽象接口），可运行于 js / wasm-gc / native 三个后端。
2. **崩溃安全**：任意时刻断电或进程被杀，重启后数据仍等于"某个操作前缀"
   的结果——不多（不允许幽灵写入）不少（不丢已确认写入）。
3. **可教学**：每个磁盘字节都有格式规范（[format.md](format.md)），
   每处设计取舍都有理由记录（本文 §6）。

## §2 架构总览

```
                    ┌─────────────┐
   put/delete ────► │  memtable   │  skip list（最新写入）
        │           │  (in-mem)   │
        ▼           └──────┬──────┘
      WAL 缓冲             │ flush（先落 WAL 再落表）
        │           ┌──────▼──────┐
        │           │  L0 表 × n  │  每次 flush 一张，键区间可重叠
        │           └──────┬──────┘
        │                  │ compact（非底层选择性归并，l0 ≥ 4 触发；保留墓碑）
        │           ┌──────▼──────┐
        │           │  L1 表 × n  │  键区间两两不相交，命名 L1_<S>_<G>
        │           └──────┬──────┘
        │                  │ compact_l2（底层选择性归并，L1 尺寸触发；抑制墓碑）
        │           ┌──────▼──────┐
        └─────────► │  L2 表 × n  │  键区间两两不相交，命名 L2_<S>_<G>
                    └─────────────┘
```

L1/L2 归并输出按 `table_size_limit`（默认 2 MiB）按键序拆分，每张表名携带
自己的水位线 `S`（该片最大序列号）与全局表计数器 `G`（会话内递增，恢复时
续号），详见 [format.md §1/§6](format.md#1-文件集)。

组件（`src/` 下）：

| 文件 | 职责 |
|---|---|
| `memtable.mbt` | 跳表 memtable，支持原地更新与有序遍历 |
| `wal.mbt` | 组提交预写日志（内存缓冲 + 整文件封存） |
| `sstable.mbt` | SSTable v2 读写、索引、bloom 过滤器、惰性游标 |
| `iter.mbt` | 归并迭代器：多源按键合并，墓碑抑制，序列号裁决 |
| `db.mbt` | 引擎：写路径、flush、compact、recover、stats |
| `crc32.mbt` | CRC-32（IEEE），兼作 bloom 种子哈希 |
| `options.mbt` | 调参（memtable 上限、块大小、L0 压缩触发数、L2 触发条件） |
| `clicore/` | 命令引擎：解析 argv 执行 set/get/del/scan/flush/compact/stats |
| `cli/` | `regolith` 可执行入口（argparse 子命令） |
| `demo/` | 端到端演示程序 |

## §3 写路径与 flush 顺序

写路径分四步，顺序是崩溃安全的核心：

1. 分配全局递增序列号 `seq`，写入 memtable（跳表两段式 put：先搜索，
   命中则原地替换值/序列号，未命中才新建节点链入）。
2. 同一条记录追加进内存 WAL 缓冲（组提交：缓冲不落盘，攒到 flush 一起写）。
3. `flush()`（显式，或 memtable 超过 `memtable_limit` 时自动触发）：
   1. **先把整个 WAL 缓冲写成 `WAL` 文件**——此时所有未成表的写入已持久化；
   2. 构建并写 L0 表；
   3. 清空 WAL 缓冲并写回空的 `WAL` 文件——memtable 已在表中持久化；
   4. 换入新 memtable。
4. 若 L0 表数 ≥ `l0_compaction_trigger`（默认 4），flush 末尾自动 compact
   （L1 非底层归并），随后若 L1 尺寸达到 L2 触发条件再自动 compact_l2
   （见 §6）。

这个顺序保证：崩溃点无论落在哪一步之间，恢复时写入要么整体存在
（WAL 或表里至少有一份），要么整体不存在（操作前缀语义）。

## §4 崩溃安全与恢复

**核心不变量**：数据库落盘状态 = `checkpoint ∪ WAL 缓冲的前缀`，
其中 checkpoint 由 L0/L1/L2 表构成。

恢复算法（实现于 `Db::recover`，格式细节见 [format.md §7](format.md#7-恢复算法)）：

- 多文件分级后，**全局水位线不再成立**（一张 L2 的 S 可能来自不含某键的
  选择性归并），覆盖判定改为**按键区间**：L1 keep-all（L1 输出不吞并所有
  重叠 L1，区间推断对 L1 不健全，陈旧表靠 S 降序读路径命中、下次压缩回收）；
  L2 表被"若干 S ≥ S_T 的 L2 表"的键区间**并集**覆盖则丢弃（L2 归并恒吞并
  所有重叠 L2，重叠必成输入链，健全）；L0 表被 S ≥ 其 max_seq 的 L1 表
  区间并集覆盖则丢弃（compact 恒合并全部 L0）。旧格式（无 G 段）表沿用
  旧水位线规则。
- WAL 的"尾巴"（半条记录）按 [format.md §3](format.md#3-wal-记录格式)
  的规则截断并立即自愈写回；有效前缀**全量重放**，不做跳过（磁盘 WAL 只会
  是最后一次封存的记录，批内后写覆盖先写，重放后每键必得最新版本）。
- 压缩输出的新表全部写完并校验通过后，输入按 **S 升序** 删除（compact_l2
  先删 L2 输入再删 L1 输入）：任何崩溃前缀都把最新版本（含墓碑所在的表）
  留在盘上，恢复的库永远读到最新值，无复活窗口。

这套设计让每个恢复动作都有清晰语义：表可以被整体丢弃（因为被覆盖），
WAL 可以被截断（因为只丢未提交尾巴），不存在需要"部分回滚一张表"的模糊地带。

**验证**：`tools/sim_crash.py` 是全状态 Python 模拟器，用 200 个随机种子
在模拟存储层上注入任意时刻崩溃（含写表中途断电），断言恢复结果与
"模型 = 已持久化日志重放"完全一致；同一套场景在 `src/crash_test.mbt`
以故障注入存储驱动 MoonBit 引擎本体双份执行。两套实现互相独立，
交叉验证恢复逻辑。

## §5 读取路径

- **点查 `get(k)`**：先查 memtable（最新），再按文件新→旧查 L0 表，然后查
  L1，miss 落 L2。每张表先过 bloom
  （[format.md §5](format.md#5-bloom-过滤器leveldb-式双哈希)）：
  权威否定直接跳过整表，避免大多数不存在的键付出磁盘读。
- **扫描 `scan()`**：归并迭代器把 memtable + 全部 L0 + L1 + L2 的游标按
  键序合并。**墓碑抑制**：同键多版本（不同 seq）只留最新者；最新版本是
  墓碑（删除）则该键不出现。L0 表间键重叠因此对外不可见——用户看到的
  永远是一份去重后的有序视图。
- **批量写 `write(batch)`**：WriteBatch 里任意多条 put/delete 一次调用
  提交——memtable 拿到一段连续序列号，WAL 只有一条批量记录
  （[format.md §3](format.md#3-wal-记录格式)），崩溃恢复时有效前缀截断
  规则保证整批要么全部重放要么全部丢弃，与单写同一语义。
- SST 游标按块惰性解析：扫描大表不物化整表，解析错误通过 `error()` 上报
  而不是崩溃。
- **范围迭代器 `RangeIterator`**：在归并迭代器外套一层 [lo, hi) 界——
  键序升序，所以第一个 ≥ hi 的键之后不可能再出现界内键，可提前终止，
  不必走完整库。`scan_prefix(p)` 是其特例（hi = 前缀的后继键），
  `scan_range(start, end)` 是通用形式，end 为空表示无上界。
- **快照 `Snapshot`（迭代器句柄）**：`db.snapshot()` 冻结当前状态——
  memtable 全量拷贝 + 钉住当前 L0/L1/L2 表。快照时刻 memtable 内所有条目
  seq ≤ 水位线（它就是水位线），被钉住的表也只含快照前的条目，因此
  **无需按 seq 过滤**，拷贝即状态。快照上的 `get/scan/scan_prefix/
  scan_range` 与 Db 同构，在活库继续写、flush、压缩期间保持同一视图：
  暂停 = 停止调用 next；恢复 = 在同一快照上重新打开迭代器（或
  `scan_range(上次停下的键, …)`）。压缩要删旧表时，被活跃快照钉住的表
  进 pending 延迟删除，最后一个持有者 `close()` 时物理清除。

## §6 设计决策记录

| 决策 | 理由 |
|---|---|
| **WAL 组提交**（整文件写，无追加/fsync） | `x/fs` 只提供整文件 IO；组提交把"每条写入一次落盘"摊薄为"每次 flush 一次落盘"，且天然支持崩溃时整体截断的语义。代价：flush 前崩溃丢失未 flush 前缀——但 flush 是写入确认的边界，语义自洽 |
| **L1 用 `S = max_seq` 命名与覆盖** | 恢复时无需 manifest 即可判定哪些表被覆盖；文件名就是水位线 |
| **跳表两段式 put**（先搜索后建节点） | 同键更新原地替换而非新建节点，保证 memtable 键唯一，归并迭代器无需在 memtable 内再裁决版本 |
| **紧凑双校验和**（`crc` 包 body + `crc2` 包 footer） | 任意单字节翻转必被捕获，读操作永不返回静默错误数据；两层防止 footer 本身被篡改 |
| **bloom 存原始哈希、finish 时定模** | `m_bits` 取决于最终键数，写入阶段无法定模；存 32 位哈希而非位图让 set/query 共享同一哈希函数，**无假阴性** |
| **单线程、无锁** | 嵌入式场景下写入天然串行；无共享可变状态，后端移植零成本（wasm-gc 无线程） |
| **存储抽象 `Storage`**（`Memory` / `fs` 两种实现） | 引擎逻辑可在内存镜像上做确定性的崩溃注入测试，与真实文件系统行为解耦 |
| **compact 后旧表先写后删、新表名必全新（`L<ℓ>_<S>_<G>`）** | 新表全部写完并校验通过才删输入（崩溃落在中途时等价于回到 compact 前状态）；G 计数器保证每次压缩输出物理上不可能覆盖旧表——修复 v0.3 重复压缩同名覆盖后删除导致丢数据的缺陷。重复压缩无新写入时自然 no-op（L0/L1 空即返回），第二次起零文件操作 |
| **分级压缩 L0→L1→L2，选择性归并 + 按 `table_size_limit` 拆分** | 单文件全量归并的压缩成本随库增长；多文件下 compact 只并全部 L0 + 区间重叠的 L1，compact_l2 挑最旧 L1 + 全部区间重叠的 L1/L2（顺带清扫崩溃残留的陈旧表），输出超限按键序拆分为区间不相交的多张表。写放大受控（LevelDB target_file_size 同款参数），无需 manifest（区间覆盖推断见 §4） |
| **L1 保留墓碑、L2 抑制墓碑** | L1 之上的删除必须继续压制 L2 里被删键的旧版本（丢了墓碑键就复活）；L2 是底层，墓碑所能覆盖的一切都在归并输入内，抑制后 S 只计存活条目，空表即全删清空三层 |
| **L2 触发条件：`l1_bytes ≥ l2_size_trigger` 且 `l2_bytes == 0 或 l1_bytes × l2_size_ratio ≥ l2_bytes`** | 小库不必为 L2 付第二次归并代价；L1 长不大时也不用急着归并进 L2（写放大受控） |
| **快照 = memtable 全量拷贝 + 钉住表，不做 seq 过滤** | 快照时刻 memtable 全部条目 seq ≤ 水位线、被钉表只含更早条目，拷贝即完整状态。相比 LevelDB 的 seq 过滤读，实现更简单、读路径零额外判断；代价是建快照 O(memtable 大小) |
| **快照钉住的表延迟删除，显式 `close()` 释放** | 压缩合并掉的旧表若被活跃快照引用则进 pending 列表，最后一个持有者 close 时物理删除。不 close 只占内存与磁盘、不影响正确性，重开数据库由恢复算法清理。显式 close 是 LevelDB/BoltDB 同款惯例（moon 0.1.20261012 无 Drop trait，见 moonbit-2026-toolchain-syntax 记忆） |
| **键压缩 v3（前缀共享 + 块内重启点），旧表兼容读** | 补齐 LevelDB 能力集（申报书 §2）：前缀化键共享前缀只写一次、块内点查由重启点二分升级；v1/v2 表照常读，旧表随压缩渐次并入 v3。详见 [design-prefix-compression.md](design-prefix-compression.md)（决策记录含 crc2 自排除、未来格式拒绝等） |
| **键序 = 逐字节字典序（`lexical_compare`）** | `Bytes::compare` 先比长度再比字节，混合长度键会破坏跳表/索引/归并的不变量，且让前缀扫描提前终止。全库键序统一用 `Bytes::lexical_compare`（format.md §3 有同样约定） |
| **游标逐条校验键严格升序** | CRC 只能查字节损坏，查不出"键重复/乱序"这类语义损坏（demo-data 事故：旧版本 memtable 重复节点 bug 写入的表带重复键，被压缩静默归并传播）。游标每读一条比一次前键，违规即 `Corrupt`——一次比较的代价，换来"语义损坏绝不静默传播" |

## §7 并发与性能特性

- 引擎单线程，无锁、无全局可变状态；多线程使用者自行串行化或各开一个 Db。
- 点查最坏 O(表数 × 块内扫描)，实际由 bloom 短路 + 索引二分 + v3 块内
  重启点二分（最多扫 `restart_interval` 条）构成；扫描为 O(总条目) 的归并。
- memtable 默认上限 4 MiB，SST 块默认 4 KiB，L0 ≥ 4 触发压缩，
  L1 ≥ 4 MiB（且相对 L2 达到 4 倍）触发底层归并——均可通过 `Options` 调整。
