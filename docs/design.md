# Regolith 设计文档

## §1 目标与定位

Regolith（月壤）是一个嵌入式的 LSM-tree 键值存储，用 MoonBit 从零实现，
仅依赖 moonbitlang/core 与 moonbitlang/x 两个官方包。设计目标：

1. **可移植**：纯 MoonBit 实现，不依赖任何系统调用（文件 IO 全部经由
   `moonbitlang/x/fs` 的抽象接口），可运行于 js / wasm-gc / native 三个后端。
2. **崩溃安全**：任意时刻断电或进程被杀，重启后数据仍等于"某个操作前缀"
   的结果——不多（不允许幽灵写入）不少（不丢已确认写入）。
3. **可教学**：每个磁盘字节都有格式规范（[format.md](format.md)），
   每处设计取舍都有理由记录（本文 §6）。

## §2 架构总览

```
                    ┌─────────────┐
   put/delete ────► │  memtable   │  skip list（最新写入）
        │           │  (in-mem)   │
        ▼           └──────┬──────┘
      WAL 缓冲             │ flush（先落 WAL 再落表）
        │           ┌──────▼──────┐
        │           │  L0 表 × n  │  每次 flush 一张，键区间可重叠
        │           └──────┬──────┘
        │                  │ compact（全量归并，l0 ≥ 4 触发）
        │           ┌──────▼──────┐
        └─────────► │  L1 表 ≤ 1  │  全量合并结果，命名带水位线
                    └─────────────┘
```

组件（`src/` 下）：

| 文件 | 职责 |
|---|---|
| `memtable.mbt` | 跳表 memtable，支持原地更新与有序遍历 |
| `wal.mbt` | 组提交预写日志（内存缓冲 + 整文件封存） |
| `sstable.mbt` | SSTable v2 读写、索引、bloom 过滤器、惰性游标 |
| `iter.mbt` | 归并迭代器：多源按键合并，墓碑抑制，序列号裁决 |
| `db.mbt` | 引擎：写路径、flush、compact、recover、stats |
| `crc32.mbt` | CRC-32（IEEE），兼作 bloom 种子哈希 |
| `options.mbt` | 调参（memtable 上限、块大小、压缩触发数） |
| `clicore/` | 命令引擎：解析 argv 执行 set/get/del/scan/flush/compact/stats |
| `cli/` | `regolith` 可执行入口（argparse 子命令） |
| `demo/` | 端到端演示程序 |

## §3 写路径与 flush 顺序

写路径分四步，顺序是崩溃安全的核心：

1. 分配全局递增序列号 `seq`，写入 memtable（跳表两段式 put：先搜索，
   命中则原地替换值/序列号，未命中才新建节点链入）。
2. 同一条记录追加进内存 WAL 缓冲（组提交：缓冲不落盘，攒到 flush 一起写）。
3. `flush()`（显式，或 memtable 超过 `memtable_limit` 时自动触发）：
   1. **先把整个 WAL 缓冲写成 `WAL` 文件**——此时所有未成表的写入已持久化；
   2. 构建并写 L0 表；
   3. 清空 WAL 缓冲并写回空的 `WAL` 文件——memtable 已在表中持久化；
   4. 换入新 memtable。
4. 若 L0 表数 ≥ `l0_compaction_trigger`（默认 4），flush 末尾自动 compact。

这个顺序保证：崩溃点无论落在哪一步之间，恢复时写入要么整体存在
（WAL 或表里至少有一份），要么整体不存在（操作前缀语义）。

## §4 崩溃安全与恢复

**核心不变量**：数据库落盘状态 = `checkpoint ∪ WAL 缓冲的前缀`，
其中 checkpoint 由 L0/L1 表构成。

恢复算法（实现于 `Db::recover`，格式细节见 [format.md §7](format.md#7-恢复算法)）：

- L1 表携带其最大序列号 `S`（文件名的一部分），**覆盖语义**由此而来：
  `seq ≤ S` 的一切条目都在 L1 里。因此恢复时 `max_seq ≤ S` 的 L0 表
  整体丢弃，WAL 中 `seq ≤ S` 的记录跳过。
- WAL 的"尾巴"（半条记录）按 [format.md §3](format.md#3-wal-记录格式)
  的规则截断并立即自愈写回。

这套设计让每个恢复动作都有清晰语义：表可以被整体丢弃（因为 L1 覆盖），
WAL 可以被截断（因为只丢未提交尾巴），不存在需要"部分回滚一张表"的模糊地带。

**验证**：`tools/sim_crash.py` 是全状态 Python 模拟器，用 200 个随机种子
在模拟存储层上注入任意时刻崩溃（含写表中途断电），断言恢复结果与
"模型 = 已持久化日志重放"完全一致；同一套场景在 `src/crash_test.mbt`
以故障注入存储驱动 MoonBit 引擎本体双份执行。两套实现互相独立，
交叉验证恢复逻辑。

## §5 读取路径

- **点查 `get(k)`**：先查 memtable（最新），再按文件新→旧查 L0 表，最后查 L1。
  每张 v2 表先过 bloom（[format.md §5](format.md#5-bloom-过滤器leveldb-式双哈希)）：
  权威否定直接跳过整表，避免大多数不存在的键付出磁盘读。
- **扫描 `scan()`**：归并迭代器把 memtable + 全部 L0 + L1 的游标按
  键序合并。**墓碑抑制**：同键多版本（不同 seq）只留最新者；最新版本是
  墓碑（删除）则该键不出现。L0 表间键重叠因此对外不可见——用户看到的
  永远是一份去重后的有序视图。
- SST 游标按块惰性解析：扫描大表不物化整表，解析错误通过 `error()` 上报
  而不是崩溃。

## §6 设计决策记录

| 决策 | 理由 |
|---|---|
| **WAL 组提交**（整文件写，无追加/fsync） | `x/fs` 只提供整文件 IO；组提交把"每条写入一次落盘"摊薄为"每次 flush 一次落盘"，且天然支持崩溃时整体截断的语义。代价：flush 前崩溃丢失未 flush 前缀——但 flush 是写入确认的边界，语义自洽 |
| **L1 用 `S = max_seq` 命名与覆盖** | 恢复时无需 manifest 即可判定哪些表被覆盖；文件名就是水位线 |
| **跳表两段式 put**（先搜索后建节点） | 同键更新原地替换而非新建节点，保证 memtable 键唯一，归并迭代器无需在 memtable 内再裁决版本 |
| **紧凑双校验和**（`crc` 包 body + `crc2` 包 footer） | 任意单字节翻转必被捕获，读操作永不返回静默错误数据；两层防止 footer 本身被篡改 |
| **bloom 存原始哈希、finish 时定模** | `m_bits` 取决于最终键数，写入阶段无法定模；存 32 位哈希而非位图让 set/query 共享同一哈希函数，**无假阴性** |
| **单线程、无锁** | 嵌入式场景下写入天然串行；无共享可变状态，后端移植零成本（wasm-gc 无线程） |
| **存储抽象 `Storage`**（`Memory` / `fs` 两种实现） | 引擎逻辑可在内存镜像上做确定性的崩溃注入测试，与真实文件系统行为解耦 |
| **compact 后旧 L0 直接删、新 L1 幂等覆盖** | 文件名确定 + 覆盖语义，崩溃落在 compact 中途时旧表已删新表未成，则等价于回到 compact 前状态（恢复重放 WAL 前缀即可） |

## §7 并发与性能特性

- 引擎单线程，无锁、无全局可变状态；多线程使用者自行串行化或各开一个 Db。
- 点查最坏 O(表数 × 块内线性扫描)，实际由 bloom 短路 + 索引二分 + 块内
  顺序扫描构成；扫描为 O(总条目) 的归并。
- memtable 默认上限 4 MiB，SST 块默认 4 KiB，L0 ≥ 4 触发压缩——
  均可通过 `Options` 调整。
