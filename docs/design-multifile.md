# 多文件分级压缩设计稿（v0.4，初审驳回三项缺陷修复方案）

> 状态：**待审**。按项目惯例，格式与恢复语义变更前先出设计稿。
> 对应驳回理由：① flush 未 fsync 却承诺持久性；② 重复 L2 压缩覆盖后删除
> 同名文件导致重启丢数据；③ 多层单文件全量归并，距成熟 LSM 有差距。

## 一、缺陷②：覆盖后删除同名文件（正确性，最高优先）

**根因**（已从代码确认）：`compact()`/`compact_l2()` 的输出名都是
`L<ℓ>_<S>.sst`，S = 本次归并的最大序列号。没有新写入时重复压缩 → S 不变
→ 同名 → `write` 原地覆盖唯一的好副本（覆盖本身还是撕裂写风险）→ 随后
`release_file(old)` 又把同名旧文件删掉 → 重启后 L2 全丢。

**修法（结构性杜绝，不是打补丁）**：

1. 新命名 `L1_<S>_<G>.sst` / `L2_<S>_<G>.sst`，其中 S = 该表最大序列号
   （水位线，保留原语义），**G = 全局表计数器**：会话内每写一张表递增，
   恢复时取现存最大 G + 1 续号。每次压缩输出必是全新文件名，物理上不可
   能覆盖旧表；旧表删除发生在所有新表写完并校验通过之后。
2. 新设计下重复压缩**无输入即 no-op**：`compact` 在 L0 为空时直接返回，
   `compact_l2` 在 L1 为空时直接返回——评审所述"重复执行 L2 压缩"场景
   第二次起不产生任何文件操作。
3. 旧格式名 `L1_<S>.sst`（无 G 段）按 G=0 解析，存量数据向后兼容。

**回归测试**：put → flush → compact → compact_l2 → 再 compact → 再
compact_l2（全程无新写）→ close → reopen → 数据完好（Memory + File 双
存储），并断言第二次起文件列表零变化。

## 二、缺陷③：多文件 L1/L2 + 选择性压缩（成熟 LSM 分层）

### 内存结构与文件命名

| 层 | 现状 | 新设计 |
|---|---|---|
| L0 | 多文件，每 flush 一张 | 不变 |
| L1 | ≤1 张（单文件全量归并） | **多张，键区间两两不相交**，数组按 S 降序维护 |
| L2 | ≤1 张 | **多张，键区间两两不相交**，数组按 S 降序维护 |

每张表带元数据 `{name, reader, seq(S), min_key, max_key, bytes}`。
`min_key`/`max_key` 用于区间重叠判定（新增 `SstReader::first_key()`，
`max_key` 复用索引末键）。L1/L2 数组按 S 降序：新表先查，崩溃残留的
陈旧重叠表靠序列号归并保证读到新值。

### compact()：L0 → L1（全量 L0 + 选择性 L1）

- 触发：L0 ≥ `l0_compaction_trigger`（不变）；L0 空则 no-op。
- 输入：**全部 L0 表** + **所有与 L0 总区间重叠的 L1 表**（选择性，
  不再全并；L0 表天然互相重叠，必须全取）。
- 归并：墓碑保留（L1 非底层）。
- 输出：按新增 `Options::table_size_limit`（默认 2 MiB，LevelDB 同款
  target_file_size）**拆分**为多张 `L1_<S>_<G>`，每张的 S = 该片最大
  序列号。拆分依赖新增 `SstBuilder::approx_size()`。
- 删除：全部新表写完并 `parse` 校验后才删输入（含快照钉住延迟删除）。

### compact_l2()：L1 → L2（选择性，挑一张合并）

- 挑选：S 最小（最旧）的 L1 表（确定性策略）。
- 输入：该表 + **所有与其区间重叠的其它 L1 表**（顺带清扫崩溃残留的
  陈旧重叠 L1，这是抑制墓碑安全的关键，见下）+ **所有区间重叠的 L2 表**。
- 归并：墓碑抑制（L2 为底层）。
- 输出：按 `table_size_limit` 拆分为多张 `L2_<S>_<G>`；全墓碑时只删输入
  不写表（现行为保留）。
- `maybe_compact_l2`：改为循环，每轮一次选择性归并，直到门限不满足或
  L1 空（每轮至少消耗一张 L1 表，必终止）。

### 墓碑抑制安全性论证（评审关注点）

抑制 k 的墓碑 ⇔ 不存在任何存活的 k 旧版本。归并输入 = 选中 L1 + 所有
区间重叠的 L1 + 所有区间重叠的 L2：
- L2 中 k 的所有旧版本：区间重叠的 L2 **全部**入参 ✓；
- L1 中 k 的旧版本：区间不相交的 L1 不含 k；重叠的（仅崩溃残留）
  全部入参 ✓；
- L0 只可能含 **更新** 的 k（seq 更大），不影响抑制 ✓。

### 恢复规则（无 manifest，区间覆盖推断）

拆片输出 + 选择性归并带来的新事实：全局水位线（"S 覆盖一切"）不再成立，
恢复必须按**键区间**判定覆盖。规则如下：

1. **L1 keep-all**：所有 CRC 有效的 L1 表全部保留（L1 输出不吞并所有
   区间重叠的 L1，区间覆盖推断对 L1 不健全）。读路径按 S 降序命中，
   陈旧表在下次压缩触碰其区间时被回收。
2. **L2 区间并集覆盖**：L2 表 T 若其键区间被"若干张 S ≥ S_T 的 L2 表"
   的区间**并集**完全覆盖，则丢弃。健全性：L2 归并恒吞并所有区间重叠
   的 L2 表，重叠区间必成输入链（新表 ⊇ 旧表的数据），并集覆盖 ⟹
   数据已归入覆盖表。此规则同时解决"抑制墓碑 + 旧 L2 残留 = 复活"的
   崩溃窗口。
3. **L0 区间并集覆盖**：L0 表 T 若其键区间被"若干张 S ≥ T 的 max_seq 的
   L1 表"的区间并集完全覆盖，则丢弃（compact 恒合并全部 L0，健全）。
   L2 不参与（选择性归并不健全）；**旧格式 L2（无 G 段）除外**：旧设计
   L2 是全量归并，保留原"m ≤ 旧 L2 的 S 即覆盖"规则以兼容存量库。
4. **旧格式 L1 兼容**：无 G 段的 L1 表（旧设计单表）若存在 S ≥ 它的旧
   格式 L2，则丢弃（旧 L2 是全量归并，健全）；新格式表之间不适用。
5. **WAL 全量重放**：不做跳过。多文件下全局 cover_s 不健全（L2 的 S
   可能来自不含该键的并归）。全量重放健全：磁盘 WAL 只可能是最后一次
   封存的记录（或清盘 LostWrite 残留的同一批），批内后写覆盖先写，
   重放进 memtable 后每键必得最新版本，与表中一致。
6. G 计数器 = 现存最大 G + 1；L0 计数器不变；next_seq = 全库最大 seq + 1。

### 输入删除顺序（崩溃窗口读正确的关键）

压缩输出的新表全部写完并校验后，按 **S 升序（旧表先删）** 删除输入，
compact_l2 先删全部 L2 输入再删 L1 输入：任何崩溃前缀都会把最新版本
（含墓碑所在的表）留在盘上——读路径按 S 降序命中，恢复的库永远读到
最新值；抑制墓碑时旧版本所在的 L2 表必先于持墓碑的 L1 表被删，无复活
窗口。

### 读路径

`get`/`scan` 遍历 L1、L2 数组（S 降序），合并迭代器多流归并（已有
MergeIterator 天然支持任意流数）。快照钉住 L1/L2 从"单表"改为"表数组"。

## 三、缺陷①：持久性契约诚实化（flush 与 fsync）

**事实核查**：`moonbitlang/x/fs` 当前 API 无 fsync（PR #341 仍 open 未
合并，含 append/sync/rename）。零 FFI、零 unsafe、仅官方包是项目红线
（申报书核心卖点），红线内**不可能**实现真 fsync。

**修法：让承诺等于实现**（LevelDB 默认 `WriteOptions{sync=false}` 同款
契约，业界标准语义）：

- 准确契约：`flush` 返回 = 全部字节已通过 write 交给**操作系统**
  （且写表后立即回读 + 双层 CRC 校验，证明字节已入 OS 缓冲层）；
  **进程级崩溃**（进程被杀）→ WAL 封存顺序保证恢复 = 已确认操作前缀；
  **掉电/内核崩溃** → 数据可能丢最近写入，需 fsync 才能保证，该能力
  随 x/fs 上游 sync API（跟踪 #341）合并后以显式选项接入。
- 落地：新增 `docs/durability.md`（分故障等级声明 + 论证 + 上游跟踪）；
  改写 README「`set`/`del`/`batch` 返回 `ok` 时数据已落盘」等过度承诺、
  申报书第 19/43 行持久性表述、acceptance 相关措辞。
- 备选（**不推荐**，需你拍板）：打破零 FFI 红线，加 per-backend extern
  fsync —— 真掉电持久，但申报书"纯 MoonBit 零 FFI"核心定位作废。
