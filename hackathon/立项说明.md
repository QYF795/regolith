# 立项说明（MoonBit 国产基础软件生态开源大赛）

> 本文件用于赛事报名（11 月轮），直接复制到报名表单相应栏目。

## 项目名称

**regolith（月壤）—— 纯 MoonBit LSM-tree 嵌入式 KV 存储引擎**

## 赛道

新项目赛道（方向一：嵌入式数据库内核）

## 一句话

纯 MoonBit、仅依赖官方 core + x/fs 的嵌入式 LSM-tree 键值引擎：WAL 组提交、跳表 memtable、bloom 过滤 SSTable、多文件分级压缩（L0→L1→L2 选择性归并，输出按 table_size_limit 拆分）；任意时点崩溃可恢复，任意字节损坏可检出，91 项测试三后端全绿。

## 定位与生态关系

1. **填补生态空白**：MoonBit 生态目前没有可用的嵌入式数据库内核（加密、图像、PDF、数据库驱动等方向多为空白，本项目立项前已逐一排雷）。regolith 面向需要在进程内持久化有序键值数据的场景：边缘设备、CLI 工具、wasm 应用。
2. **生态共创**：数据库类场景暴露了 x/fs 缺少 `append`/`fsync`/`rename` 原语的问题——本项目向上游提交了 [moonbitlang/x PR #341](https://github.com/moonbitlang/x/pull/341)（文件追加/同步/重命名）与 [moonbitlang/moon PR #2293](https://github.com/moonbitlang/moon/pull/2293)（wasm 运行时三个 host import），regolith 的 WAL 组提交设计正是从这一现状出发并给出了工程解法。
3. **质量可核验**：字节级磁盘格式规范（docs/format.md）、损坏矩阵、设计决策记录（docs/design.md）、7+ 项验收清单（docs/acceptance.md）；崩溃一致性由 200 种子故障注入测试与一个独立 Python 全状态模拟器（tools/sim_crash.py）双重对照。

## 技术方案

- **写路径**：put/delete 先入确定性种子跳表 memtable 并记 WAL（组提交：整文件封存而非逐条追加，规避 x/fs 无 append/fsync 的限制）；memtable 超限时按 crash-safe 顺序 flush（先封 WAL → 再建表写表并当场完整校验（双层 CRC）→ 再清 WAL → 最后换表）；L0 积满触发压缩——compact 合并全部 L0 + 区间重叠 L1（保留墓碑），compact_l2 挑最旧 L1 + 区间重叠 L1/L2（抑制墓碑），输出按 table_size_limit 拆分为多张 `L1_<S>_<G>.sst` / `L2_<S>_<G>.sst`（S = 片内最大序列号，G = 全局表计数器，新表物理上不可能覆盖旧表），恢复按键区间并集覆盖判定，无需 manifest。
- **读路径**：点查按 memtable → L0（新→旧）→ L1 短路；每张 v2 表先过 bloom（双哈希、无假阴性、absent 键假阳性约 0.8%）。扫描为惰性归并迭代器（按块解析不物化整表），`scan_prefix(p)` 前缀扫描利用键序提前终止。
- **键序 = 逐字节字典序**：修复了 `Bytes::compare` 长度优先比较破坏排序不变量的隐患（混合长度键回归测试守护）。
- **崩溃安全**：任意时点崩溃恢复到 checkpoint ∪ 某操作前缀——torn 表丢弃、L2/L0 被区间并集覆盖的旧表丢弃（L1 keep-all）、WAL 有效前缀全量重放；由 FailpointStorage 故障注入（丢写/撕裂写，5 类故障）驱动 200 种子 × 40 步模型对照。
- **损坏检测**：双层 CRC-32（crc 包 body + crc2 包 footer），任意单字节翻转必被拒绝，绝不静默返回错数据。语义损坏同样拦截：游标逐条校验键严格升序，重复/乱序键（CRC 不可见）读取即报 `Corrupt`，压缩拒绝归并传播。
- **质量**：`moon check --deny-warn` 零警告；91 项测试在 js / wasm-gc / native 三后端全绿（native 由 CI 验证）；7 项性能基准随 CI native 任务回归（数字见 docs/bench.md）；5 万随机操作 soak 模型对照（周期 flush/compact/compact_l2/reopen）；仅依赖 `moonbitlang/x`。
