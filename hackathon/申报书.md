# 项目申报书

## 1. 项目名称

月壤（regolith）—— 纯 MoonBit LSM-tree 嵌入式 KV 存储引擎
（https://github.com/QYF795/regolith）

## 2. 项目简介

月壤是一个跑在进程里的键值数据库：API 只有 put/get/delete/scan 几个函数，数据落到本机磁盘，重启不丢。底层是经典的 LSM-tree 结构——写入先进内存跳表并记 WAL 日志，攒满一批刷成排序表文件，后台归并压缩。面向「应用要持久化数据，但不想为它再挂一个独立数据库进程」的场景。全部用 MoonBit 写成，只依赖官方 x/fs 一个包。

## 3. 项目方向，通用性说明

方向一：嵌入式数据库内核。通用性来自两点：不预设数据模型——键值都是任意字节，URL 缓存、配置存储、日志索引、用户数据，上层想怎么组织都行；不预设运行环境——js / wasm-gc / native 三后端跑同一套代码和测试，桌面应用、CLI 工具、wasm 应用都能内嵌。

## 4. 预期使用场景

1. **CLI 工具的本地状态**。命令行工具要记住上次同步位置、缓存、配置历史：用 SQLite 嫌重，自己写文件要操心原子性。内嵌月壤后，一次 put 加一次 flush 就是落盘确认，崩溃恢复是引擎的事。
2. **桌面应用的索引与缓存**。笔记软件按前缀查标题，scan_prefix 直接给结果；数据多了 bloom 过滤器让点查跳过无关表文件，冷热数据由压缩自动整理。
3. **游戏存档**。存档本质是键值对：玩家进度、装备、地图状态。游戏闪退不损坏存档是硬需求——月壤的恢复算法保证任意时点崩溃后回到某个写入前缀，200 种子崩溃注入测试守着这条线。
4. **wasm 应用的数据层**。浏览器环境没有文件系统也不妨碍：存储层是抽象接口，换成内存实现即可，引擎代码一行不改，同一套 API 在 js 后端跑。

## 5. 拟实现的核心功能

- **存储引擎（已完成）**：跳表 memtable + WAL 组提交 + SSTable v2（bloom 过滤器、双层 CRC 校验）
- **崩溃一致性（已完成）**：恢复算法 + FailpointStorage 故障注入（200 种子 × 40 步）+ 独立 Python 全状态模拟器双重对照
- **查询能力（已完成）**：点查、全量扫描、前缀扫描 scan_prefix（键序提前终止）
- **工程化（已完成）**：CLI（set/get/del/scan/scan_prefix/flush/compact/stats）、demo、三后端 CI、51 项测试
- **后续计划**：scan_range 区间查询与可暂停迭代器、分级压缩（多 L1 层）、mooncakes.io 发布

## 6. 原创性说明

原创项目，代码从零编写，不是移植。设计参考了经典 LSM-tree 论文和 LevelDB 的公开实现——参考的是分层结构、WAL、bloom 过滤这些公开的设计思路，代码与存储格式均为自定：L1_<S> 文件命名用最大序列号当覆盖水位线，恢复时靠文件名而非 manifest 判定表间覆盖，字节级格式有完整规范文档（docs/format.md），与 LevelDB/RocksDB 格式不兼容。依赖仅官方 moonbitlang/x 一个包；另外为补齐数据库场景缺失的文件 IO 原语（append/fsync），向上游提交了两个 PR（moonbitlang/x #341、moonbitlang/moon #2293）。
