# 项目申报书

## 1. 项目名称

月壤（regolith）—— 纯 MoonBit LSM-tree 嵌入式 KV 存储引擎
（https://github.com/QYF795/regolith）

## 2. 项目简介

月壤是一个跑在进程里的嵌入式键值引擎：API 只有 put/get/delete/scan 几个函数，数据落到本机磁盘，重启不丢。它不是 LSM 原型——完整读写路径与崩溃一致性已交付（83 项测试、三后端 CI 全绿），本期把功能面补齐到 LevelDB 能力集：原子批量写入、区间迭代器、多级分层压缩，并对外明确写入的原子性与持久性契约。全部用 MoonBit 写成，只依赖官方 x/fs 一个包。

## 3. 项目方向，通用性说明

方向一：嵌入式数据库内核。通用性来自两点：不预设数据模型——键值都是任意字节，URL 缓存、配置存储、日志索引、用户数据，上层想怎么组织都行；不预设运行环境——js / wasm-gc / native 三后端跑同一套代码和测试，桌面应用、CLI 工具、wasm 应用都能内嵌。

引擎对外提供嵌入式 KV 的三条标准契约，本期交付并在文档中逐一声明：

- **原子性**：单写与批量写都是全有或全无，崩溃后不会出现半次写入
- **持久性**：flush 为确认边界，flush 返回即已完整落盘；崩溃后恢复到已确认写入的某个前缀
- **有序性**：键按字节字典序排列，支持前缀扫描与区间遍历

## 4. 预期使用场景

1. **CLI 工具的本地状态**。命令行工具要记住上次同步位置、缓存、配置历史：用 SQLite 嫌重，自己写文件要操心原子性。内嵌月壤后，一次 put 加一次 flush 就是落盘确认；「游标 + 缓存 + 配置」多键用一次批量写原子提交，不会出现半新半旧。
2. **桌面应用的索引与缓存**。笔记软件按前缀查标题走 scan_prefix，按日期区间查日记走 scan_range；数据多了 bloom 过滤器让点查跳过无关表文件，冷热数据由分级压缩自动整理。
3. **游戏存档**。存档是键值对：玩家进度、装备、地图状态。批量写保证同一帧的多键状态原子落盘；游戏闪退不损坏存档——恢复算法保证任意时点崩溃后回到某个写入前缀，200 种子崩溃注入测试守着这条线。
4. **wasm 应用的数据层**。浏览器环境没有文件系统也不妨碍：存储层是抽象接口，换成内存实现即可，引擎代码一行不改，同一套 API 在 js 后端跑。

## 5. 拟实现的核心功能

**已完成基线（申报前已交付，全部可核验）**：

- 存储引擎：跳表 memtable + WAL 组提交 + SSTable v2（bloom 过滤器、双层 CRC 校验）
- 崩溃一致性：恢复算法 + FailpointStorage 故障注入（200 种子 × 40 步）+ 独立 Python 全状态模拟器双重对照
- 查询：点查、全量扫描、前缀扫描 scan_prefix（键序提前终止）
- 工程化：CLI（set/get/del/batch/scan/scan_prefix/scan_range/flush/compact/stats）、demo、三后端 CI、83 项测试、字节级格式规范 docs/format.md、7 项性能基准（moon bench）、5 万操作 soak 模型对照

**本期核心交付**：

- **原子批量写入 WriteBatch**：一次调用原子提交多键，WAL 单条记录承载，恢复语义与单写一致
- **区间迭代器 scan_range(start, end)**：任意键区间有序遍历，与前缀扫描共享提前终止机制
- **多级分层压缩**：L0 → L1 → L2 分级归并，层间大小比控制写放大，替代当前单 L1 全量归并；恢复时的覆盖判定随层扩展
- **持久性保证声明**：flush 为持久化边界（返回即落盘）；随 x/fs 上游 append/sync PR（moonbitlang/x #341）合并后接入显式 sync 选项
- **分发**：mooncakes.io 发布

## 6. 原创性说明

原创项目，代码从零编写，不是移植。设计参考了经典 LSM-tree 论文和 LevelDB 的公开实现——参考的是分层结构、WAL、bloom 过滤这些公开的设计思路，代码与存储格式均为自定：L1_<S> 文件命名用最大序列号当覆盖水位线，恢复时靠文件名而非 manifest 判定表间覆盖，字节级格式有完整规范文档（docs/format.md），与 LevelDB/RocksDB 格式不兼容。依赖仅官方 moonbitlang/x 一个包；另外为补齐数据库场景缺失的文件 IO 原语（append/fsync），向上游提交了两个 PR（moonbitlang/x #341、moonbitlang/moon #2293）。
